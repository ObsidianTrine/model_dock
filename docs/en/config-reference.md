## Before you start

- **Hand-editing**: `modeldock config edit` opens an editor and validates on save; while the gateway is running, changes to config.toml hot-reload automatically — no restart needed.
- **Hand-written comments and formatting are not preserved**: when the Web console or a command saves the config, ModelDock rewrites the whole config.toml — your comments and layout are lost (the settings themselves are not). Keep long-lived notes elsewhere.<!-- known tradeoff: mutateConfig reserializes the whole file; adjacent to known-issues CORRECT-03 -->
- **Placeholders**: `<id>` `<model>` `<profile>` `<client>` `<pack>` in key names stand for entry names you choose; example values are illustrative.
- **"Program-managed"**: the key is written and managed by ModelDock and listed for completeness; snapshots can restore accidental changes.

## 1. Global

Top-level keys that apply to ModelDock as a whole, written at the root of config.toml.

| Key | Type | Required | Default | Description |
|---|---|---|---|---|
| `version` | `number` | yes | `1` (do not change) | Program-managed. Config format version, migrated automatically as the program upgrades. Do not edit. |
| `language` | `'zh' \| 'en'` | no | `zh` | Interface language: `zh` Chinese, `en` English — applies to CLI output, errors and gateway log messages. The `--lang` flag and the `MODELRDOCK_LANG` env var override it temporarily. |
| `active_profile` | `string` | no | none (unset) | The active profile (an id under `[profiles.*]`) — which service "follow default route" clients actually use. |

Example:

```toml
version = 1
language = "zh"
active_profile = "ark-coding"
```

## 2. Providers (providers)

One block per upstream provider; `<id>` is a name you choose (lowercase letters, digits, underscore). Model metadata (`models`) is covered in the next section.

| Key | Type | Required | Default | Description |
|---|---|---|---|---|
| `name` | `string` | no | same as id | Provider display name; defaults to the id. |
| `base_url` | `string` | yes | — | Upstream API base URL. |
| `protocol` | `'anthropic' \| 'openai' \| 'responses'` | yes | — | Upstream protocol: `anthropic` (Anthropic-compatible), `openai` (OpenAI-compatible chat), `responses` (OpenAI Responses). |
| `auth_style` | `'bearer' \| 'x-api-key'` | yes | — | Auth header style: `bearer` (`Authorization: Bearer …`) or `x-api-key` (`x-api-key: …`). |
| `key_ref` | `string` | yes | — | Reference to the upstream API key: `file:<id>` (local secret file), `keychain:<id>` (OS keychain), `env:<VAR>` (environment variable); plaintext works but is strongly discouraged. |
| `proxy` | `'direct' \| 'env' \| string` | no | `direct` | Outbound proxy: `direct` (no proxy), `env` (follow proxy environment variables), or an explicit `http://host:port`. |
| `enabled` | `boolean` | no | `true` | Set `false` to take the service offline manually: no probing, excluded from auto routing and failover. |
| `priority` | `number` | no | `0` | Sorting weight for auto-routing candidates; higher wins. Only effective when "program picks the primary" is on. |
| `endpoints` | `{ anthropic?, openai?, responses? }` | no | none | Per-protocol base URL overrides: for vendors serving anthropic / openai / responses at different addresses; protocols without an entry fall back to `base_url`. |

Example:

```toml
[providers.<id>]
name = "ACME"
base_url = "https://api.acme.com/v1"
protocol = "anthropic"
auth_style = "bearer"
key_ref = "file:acme"
proxy = "direct"
enabled = true
priority = 10
endpoints.openai = "https://api.acme.com/openai"
```

## 3. Model metadata (models)

One entry per model, holding display metadata; actual availability is decided upstream — nothing here affects requests.

| Key | Type | Required | Default | Description |
|---|---|---|---|---|
| `display_name` | `string` | no | same as model id | Model display name; defaults to the model id. |
| `context_window` | `number` | no | none | Input context window in tokens, shown in the console. |
| `max_output` | `number` | no | none | Maximum output in tokens. |
| `capabilities` | `string[]` | no | none | Capability tags for display (e.g. `tools`, `reasoning`). |
| `source` | `'preset' \| 'fetched' \| 'manual'` | yes | — | Where the model entry came from: `preset` (built-in preset), `fetched` (pulled from the upstream catalog), `manual` (added by hand; maintained by the program). |

Example:

```toml
[providers.<id>.models.<model>]
display_name = "Fast Model"
context_window = 131072
max_output = 8192
capabilities = ["tools", "reasoning"]
source = "preset"
```

## 4. Profiles (profiles)

A profile = which provider + default model + alias mapping. A client's route points at a profile id, or `default` follows active_profile.

| Key | Type | Required | Default | Description |
|---|---|---|---|---|
| `name` | `string` | no | same as id | Profile display name; defaults to the id. |
| `provider` | `string` | yes | — | The provider id (under `[providers.*]`) this profile routes to. |
| `default_model` | `string` | no | none (upstream default) | Upstream model used when the requested model name matches no alias; if unset, the upstream default applies. |
| `aliases` | `Record<string, string>` | no | none (no rewriting) | Mapping from requested model names to upstream model names; `*` wildcards supported (e.g. `"claude-sonnet-*"`). |
| `fallback` | `string[]` | no | none (no manual chain) | Manual failover chain, tried in order when the primary is unreachable. Entries: `"<providerId>"` (pass the model through) or `"<providerId>:<modelId>"` (rewrite the model). |
| `tier` | `string` | no | unset (no isolation) | Task tier tag (free-form short label, e.g. `heavy` / `light`): basis for failover isolation — the auto fallback chain and avoid-window extras only rotate among services referenced by profiles of the same tier, so heavy tasks never silently land on cheap providers (or vice versa). Unset = no isolation; the manual chain and the manual "next" pin are not restricted. |

Example:

```toml
[profiles.<profile>]
name = "Coding"
provider = "acme"
default_model = "fast-model"
aliases = { "claude-sonnet-*" = "fast-model" }
fallback = ["backup", "backup:slow-model"]
tier = "heavy"
```

## 5. Harness attachment (harness)

One block per attached client (`<client>` is the client id, e.g. claude-code). Attach / detach is normally done with `modeldock attach` / `detach`; use this section to inspect and tweak (`mode` / `route` / `token`).

| Key | Type | Required | Default | Description |
|---|---|---|---|---|
| `mode` | `'gateway' \| 'file' \| 'direct'` | yes | — | Attach mode: `gateway` traffic goes through the local gateway; `file` the config file is managed but the client routes itself; `direct` connects straight to the upstream (no gateway). |
| `route` | `string` | no | `default` (follows the active profile) | Route: `default` follows the active profile; a concrete profile id pins the client to it; in `direct` mode, the direct target profile. |
| `direct_base` | `string` | no | written at attach | Program-managed. The direct URL actually written into the client in `direct` mode (written at attach). |
| `token` | `string` | no | written at attach | The token this client uses to reach the gateway (written at attach, or chosen by you). |
| `attached_at` | `string` | no | written at attach | Program-managed. When the client was last attached. |
| `files` | `string[]` | no | written at attach | Program-managed. Client config files under management (restored on detach). |
| `client_profiles` | `string[]` | no | written at attach | Program-managed. Client's own profiles selected at attach (e.g. dsh's desktop / web); mode switches rewrite within this scope. |
| `gateway_base` | `string` | no | written at attach | Program-managed. The gateway URL written at attach; detach matches on it precisely so your other local proxy settings are not touched. |
| `limits.rpm` | `number` | no | unlimited | Data-plane rate limit: max requests per minute for this client; excess requests get 429 (protects upstreams from a runaway client; counted in gateway memory, reset on restart). |
| `limits.daily_tokens` | `number` | no | unlimited | Daily spend cap: once this client's token usage for the day (input incl. cache + output) reaches it, requests get 429 until the next day. |

Example:

```toml
[harness.<client>]
mode = "gateway"
route = "default"
# direct_base = "https://api.acme.com/v1"  # program-managed; no need to edit
token = "mdk_..."
# attached_at = "2026-01-01T00:00:00.000Z"  # program-managed; no need to edit
# files = ["~/.claude/settings.json"]  # program-managed; no need to edit
# client_profiles = ["desktop"]  # program-managed; no need to edit
# gateway_base = "http://127.0.0.1:8687"  # program-managed; no need to edit

[harness.<client>.limits]
rpm = 60
daily_tokens = 5000000
```

## 6. Declarative adapter packs (adapter_packs)

Onboard a new client with zero code: describe which file gets which keys, then `modeldock attach <pack>` takes over.

| Key | Type | Required | Default | Description |
|---|---|---|---|---|
| `format` | `'json' \| 'toml' \| 'yaml'` | yes | — | Client config file format: `json` / `toml` / `yaml`. |
| `config_file` | `string` | yes | — | Path of the client config file (`~` supported). |
| `detect.file_exists` | `boolean` | no | none | Detection (optional): the client counts as installed only if this file exists. |
| `detect.key_path` | `string` | no | none | Detection (optional): the client counts as attached only if this JSONPath resolves in its config. |
| `upsert` | `Record<string, string>` | yes | — | Entries to write: config path expression → value template. Template variables: `{token}` `{port}` `{base_url}` `{base_url_openai}`. |

Example:

```toml
[adapter_packs.<pack>]
format = "json"
config_file = "~/.config/opencode/opencode.json"
upsert = { "$.provider.modeldock.baseURL" = "{base_url}", "$.provider.modeldock.apiKey" = "{token}" }

[adapter_packs.<pack>.detect]
file_exists = true
key_path = "$.modeldock"
```

## 7. Gateway (gateway)

Gateway listening, timeouts, logs and failover behavior. Scheduled switching (`schedule`) has its own section below.

| Key | Type | Required | Default | Description |
|---|---|---|---|---|
| `port` | `number` | no | `8687` | Gateway listen port, localhost only (127.0.0.1); if taken, auto-increments and clients get the actual port. |
| `idle_timeout_ms` | `number` | no | `600000` (10 minutes) | Max gap between upstream data (ms): a streaming answer that stalls longer than this is cut off. Raise it to tolerate long pauses (long thinking, slow upstreams). |
| `retries` | `number` | no | `1` | Retries when connecting to the upstream fails (connection errors only; an already-sent request is not re-sent). |
| `headers_timeout_ms` | `number` | no | `60000` | How long to wait for upstream response headers (ms). Non-streaming long generations can exceed 60s — raise this if you hit header timeouts. |
| `max_body_mb` | `number` | no | `16` | Request body buffering limit (MB): model alias rewriting needs the full body, oversize gets 413. Raise it for large PDFs / many attachments. |
| `log_retention_days` | `number` | no | `30` | How many days of daily request-log files to keep: older files are deleted at gateway startup and by a daily sweep; `0` = keep everything. |
| `auto_failover` | `boolean` | no | `false` (off) | Whether the program picks the primary automatically (time windows / priority / measured latency). Off (default) = the primary is whatever you pinned or the default route. Failing over when the primary is down always stays available regardless of this switch. |
| `auto_route_provider` | `string` | no | empty (automatic) | Manually pinned primary provider id: routing prefers it (over program automation and time windows); empty = the program picks by window / default route. Same as the "Current" dropdown in the console. |
| `failover_status_codes` | `number[]` | no | `[]` (no switch) | Upstream status codes that still allow switching to a backup after the response has started (e.g. `[429, 503]`); empty by default = a delivered response is passed through as-is, no switch. |
| `route_next` | `string` | no | empty (automatic order) | Manually pinned "next in line": when the primary is down, this one is tried first (ahead of the backup chain); empty = ordered automatically by priority / measured latency. |
| `auto_fallback` | `boolean` | no | `true` (on) | Automatic backup chain: beyond your manual chain, other enabled services are added as failover candidates automatically (ordered by window / priority / measured latency, models passed through); only an explicit `false` turns it off. |

Example:

```toml
[gateway]
port = 8687
idle_timeout_ms = 600000
retries = 1
headers_timeout_ms = 60000
max_body_mb = 16
log_retention_days = 30
auto_failover = false
auto_route_provider = "acme"
failover_status_codes = [429, 503]
route_next = "backup"
auto_fallback = true
```

## 8. Scheduled switching (gateway.schedule)

Prefer (or avoid) a provider during time windows, evaluated per request against the local clock; public holidays come from calendar data (holiday-cn). `windows[]` is the list of windows, one entry each.

| Key | Type | Required | Default | Description |
|---|---|---|---|---|
| `enabled` | `boolean` | no | `true` (active once windows exist) | Master switch for scheduled switching: effective by default once windows exist; `false` pauses all windows (config kept). |
| `windows[].start` | `string` | yes | — | Window start, local time `HH:mm` (inclusive). |
| `windows[].end` | `string` | yes | — | Window end, local time `HH:mm` (exclusive); less than start means overnight — the small hours belong to the window's start day. |
| `windows[].target` | `string` | yes | — | Window target: `"<providerId>"` (pass the model through) or `"<providerId>:<modelId>"` (rewrite to that model). |
| `windows[].days` | `number[]` | no | every day | Days of week the window applies (1=Mon … 7=Sun); all by default; combined with `dayFilter` by intersection. |
| `windows[].dayFilter` | `'workday' \| 'weekend' \| 'holiday'` | no | every day | Apply by calendar day type: `workday` (Mon–Fri plus makeup workdays, excluding public holidays), `weekend`, `holiday`; every day by default. Holiday data from holiday-cn. |
| `windows[].mode` | `'prefer' \| 'avoid'` | no | `prefer` | Window mode: `prefer` (default) prefer the target during the window; `avoid` steer away from the target provider (others proceed by priority; provider granularity only, model part ignored). |

Example:

```toml
[gateway.schedule]
enabled = true

[[gateway.schedule.windows]]
start = "09:00"
end = "18:00"
target = "acme"
days = [1, 2, 3, 4, 5]
dayFilter = "workday"
mode = "prefer"
```

## 12. Auto-update (update)

Where new releases are checked, downloaded and installed from.

| Key | Type | Required | Default | Description |
|---|---|---|---|---|
| `repo` | `string` | no | the public main repo | Repository to check updates from (owner/name); the public main repo by default — pair `token_ref` when pointing at a private one. |
| `api_base` | `string` | no | GitHub API | API base of the update feed (GitHub API by default); override for a self-hosted feed. |
| `token_ref` | `string` | no | none (anonymous) | Key reference for the update-feed token (optional): required for private repos; on public repos it raises the anonymous rate limit to the authenticated quota. The token itself lives in the secret store, never in plaintext here. |
| `mirror` | `string[]` | no | built-in mirror chain | Download mirror prefixes, tried in order; `[]` = mirrors off, official direct only; a built-in mirror chain by default. The checksum file always comes from the official source to guard against mirror tampering. |

Example:

```toml
[update]
repo = "ObsidianTrine/model_dock"
api_base = "https://api.github.com"
token_ref = "file:github_pat"
mirror = ["https://gh-proxy.com/", "https://ghfast.top/"]
```

## 14. Text-asset sync (sync_assets)

Whitelisted directories converged via multi-machine sync (chosen per machine; the list itself does not sync).

| Key | Type | Required | Default | Description |
|---|---|---|---|---|
| `dirs` | `string[]` | no | none (no text assets synced) | Text-asset sync whitelist: text files inside these home-relative directories converge across machines via the sync package — written when missing, skipped when identical, extra local files never deleted; a snapshot is taken before changes. ~/.modeldock and node_modules are never packaged; binaries are skipped (≤512KB per file, ≤4MB total, ≤200 files).
