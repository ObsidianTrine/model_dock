# 对外文档与用户文案写作规范（docs-writing）

> **何时读**（触发条件，命中任一必读本文件）：
> 1. 用户可见行为发生变化，要更新 `CHANGELOG.md` / `README.md` 时；
> 2. 写报错信息、Web 控制台按钮/提示等**用户可见文案**时。
>
> **受众提醒**：CHANGELOG / README 是写给**用户**看的，不是给开发者/agent 看的。
> 内部技术约定写在 AGENTS.md / docs/design.md，不要混进对外文档。

## 总原则（5 条）

1. **用户视角**：写"用户能做什么 / 修好了什么问题"，不写"实现了什么机制"。
2. **一条一事**：每条只讲一件事；**粗体短语点题** + 一两句解释。
3. **说人话**：不出现内部术语、函数名、文件路径、内部代号（用户要用的命令/路径除外）。
4. **简洁**：单条不超过 2 行；能一句话说清就不写两句；不写长段落。
5. **真实**：描述与实际行为一致——发布内容 = tag 之前的全部提交；没做的不写、做了的不漏。

## CHANGELOG.md 规范

结构遵循 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)（中文标题）：

````markdown
## [未发布]

## [X.Y.Z] - YYYY-MM-DD

一句话概述这个版本。

### 新增

- **功能点**：用户视角的一句话说明。

### 修复

- **问题现象**：现在修好了，用户得到什么。
````

- **归并规则**：打 tag 前把「未发布」段归并进版本段；日期 = 实际发布日；文末版本链接表同步补一行。
- **条目从提交翻译而来**：commit message 可以技术性，CHANGELOG 条目必须翻译成用户语言。
- **范围 = tag 之前的全部提交**：提交里有而日志漏记 = 对外失真。宁多勿漏，但纯内部改动（重构/测试/CI）不进。
- 新增分节用 `### 新增` / `### 修复`（需要时加 `### 改进`），版本导语一句话说清主题。

### 反例对照（取自 v1.0.0 整理实例）

| ❌ 内部视角 | ✅ 用户视角 |
|---|---|
| `detach` 固定还原最早一次 attach 的快照 | **断开不再冲掉自己的改动**：只回滚 ModelDock 写入的内容 |
| 修复 provider-json 默认模型未跟随钉定路由 | **切换服务后模型列表自动同步**，默认模型跟随设置 |
| openai/responses 端点出站 `/v1/v1` 双版本拼接 | **部分厂商请求 404**：修复接口地址被拼错的问题 |
| refreshBakedModelClients 按文件去重 | （纯内部优化，不进 CHANGELOG） |

## README.md 规范

- **受众 = 第一次看到项目的人**：先一句话"这是什么、解决什么问题"，再能力清单（每条写用户收益），再快速开始。
- **命令示例可直接复制运行**；链接、徽章、平台/客户端支持表格与实际保持一致。
- **新增用户可见能力时同步 README**：能力清单、命令表、支持列表三处自查。
- 保持简短：细节展开到 `docs/usage.md`，README 不堆长文。

## 代码中的用户可见文案（报错 / 界面）

- **报错信息**：说清"出了什么 + 怎么修"（与 AGENTS.md「错误信息」约定一致）；不暴露堆栈、内部变量名。
  - ❌ `planDetach failed: snapshot missing` → ✅ `断开失败：找不到还原快照。可执行 modeldock restore <harness> 列出可用快照后手动还原。`
- **界面文案**：按钮不超过 4 字、动词开头（「应用」「断开」）；提示语口语化、一句话说完。
- toast / 弹窗内容保持可复制（长报错用户需要能拷走排查）。

## 多语言文档结构（docs/en/）

- **中文是唯一事实来源**；英文版是翻译镜像，放在 `docs/en/`，文件与目录结构和中文一一对应（`README.md` / `CHANGELOG.md` / `CONTRIBUTING.md` / `SECURITY.md` / `usage.md` / `multi-machine-sync.md` / `deploy-cloud.md`）。纯内部文档（docs/design*、known-issues、backlog、RELEASE_CHECKLIST、orchestrator*、AGENTS.md 等）**不做翻译**。
- **语言切换行**：每篇对外文档 H1 标题下第一行是切换行——当前语言加粗、其他语言是相对链接；其下紧跟一行 `<!-- i18n-slot：… -->` 注释，是**新增语言的预留插入位**（在该行上方追加链接即可，对读者不可见）。
- **新增语言 = 三步**：① 新建 `docs/<lang>/` 镜像目录，结构对齐 `docs/en/`；② 在所有已有语言的切换行追加链接；③ 在本节登记该语言。
- **同步规则**：改动任何对外文档（中文）时，同一交付里更新 `docs/en/` 对应镜像；英文版里指向仅中文存在的文档（design.md 等）时直接链中文原文件并标注 "(Chinese)"。
- **互链方向**：根目录文档 ↔ `docs/en/` 用相对路径（如 `docs/en/README.md` ↔ `../../README.md`）；docs/ 下文档 ↔ `docs/en/` 同理（`en/usage.md` ↔ `../usage.md`）。

## 自检清单（每次改完过一遍）

- [ ] 只看 CHANGELOG 条目，用户能否知道"这次我能得到什么"？
- [ ] 有没有内部术语 / 函数名 / 文件路径混进来？
- [ ] 每条是否 ≤ 2 行、粗体点题？
- [ ] 描述与实际行为一致（对照 v<上一版本>..HEAD 提交记录）？
- [ ] README 的命令 / 链接 / 支持列表还准确吗？
- [ ] 对外文档改了，`docs/en/` 英文镜像同步了吗（含切换行链接未断）？
