# docs-sync（文档同步检查工作流）

代码改动导致用户可见行为变化时，确保对外文档同步更新——不靠自觉，靠 checklist。

> **何时用**：任何 `finish` 之前，作为合并前检查的一部分（与 `code-review.md` 并行做）。
> **核心问题**：代码改了但文档没跟上，是用户困惑和 issue 的主要来源。

## 检查清单（finish 前过一遍）

### CHANGELOG.md

- [ ] 这次改动有用户可见的行为变化吗？（新功能 / 修复 bug / 改了默认行为）
  - 有 → 必须在「未发布」段加条目。
  - 没有（纯内部重构 / 测试 / CI）→ 不加，跳过本节。
- [ ] 条目写法符合 `.agents/conventions/docs-writing.md`：用户视角、一条一事、粗体点题、≤2 行？
- [ ] 有没有把内部术语（函数名、文件路径、机制名）写进条目？

### README.md

- [ ] 新增了用户可见能力？→ 能力清单加一条（写用户收益，不写实现）。
- [ ] 新增 / 改了 CLI 命令或参数？→ 命令表同步更新。
- [ ] 支持列表（平台 / 客户端 / 供应商）有变化？→ 对应表格更新。

### AGENTS.md

- [ ] 流程、端口策略、工程约定有变化？→ 对应章节同步更新（AGENTS.md 是活文档）。
- [ ] 新增了工作流文件？→ 「多 Agent 并行开发约定」章节的工作流列表同步更新。

### 英文镜像（docs/en/）

- [ ] 这次改动涉及对外文档（README / CHANGELOG / CONTRIBUTING / SECURITY / docs/usage / multi-machine-sync / deploy-cloud）吗？
  - 有 → 同一交付里更新 `docs/en/` 下对应英文镜像（中文是事实来源，英文跟随；纯内部文档不翻译，结构约定见 `.agents/conventions/docs-writing.md`「多语言文档结构」）。
  - 顺手核对新旧文档顶部语言切换行的链接都未断。

### 报错 / 界面文案

- [ ] 新增或改了报错信息？→ 符合"说清出了什么 + 怎么修"，不暴露堆栈和内部变量名。
- [ ] 新增或改了界面文案？→ 按钮 ≤4 字动词开头，提示语一句话说完。

## 常见遗漏对照

| 改了什么 | 容易忘了同步什么 |
|---|---|
| 新增 CLI 子命令 | README 命令表 + CHANGELOG 条目 |
| 改了默认端口 / 路径 | AGENTS.md 端口表 + README 快速开始 |
| 新增 harness 适配器 | README 支持列表 + CHANGELOG 条目 |
| 改了报错信息 | CHANGELOG 条目（如果影响用户排查） |
| 新增工作流文件 | AGENTS.md「多 Agent 并行开发约定」列表 |

## 一句话原则

**用户能看到的变化，文档里必须能看到；用户看不到的变化，文档里不要出现。**

## 填写示例：新增 `modeldock export` 命令

假设任务目标是"新增 `modeldock export` 命令导出配置为 JSON"，`finish` 前过 checklist：

### CHANGELOG.md

- [x] 这次改动有用户可见的行为变化吗？
  - ✅ 有 → 新增了 `export` 命令
  - 已在「未发布」段添加条目：

    ```markdown
    ### 新增

    - **导出配置**：新增 `modeldock export` 命令，可导出当前配置为 JSON 文件。
    ```

- [x] 条目写法符合规范？
  - ✅ 用户视角："你能导出配置"而非"实现了 export 功能"
  - ✅ 一条一事：只讲导出
  - ✅ 粗体点题：**导出配置**
  - ✅ ≤2 行：一句话

- [x] 有没有把内部术语写进条目？
  - ✅ 没有写 `exportCommand`、`src/cli/export.ts` 等内部名

### README.md

- [x] 新增了用户可见能力？
  - ✅ 是 → 能力清单加一条："**导出配置**：一键导出当前配置为 JSON，方便备份和迁移。"

- [x] 新增 / 改了 CLI 命令？
  - ✅ 是 → 命令表加一行：

    ```markdown
    | 导出配置 | `modeldock export [output.json]` |
    ```

- [x] 支持列表有变化？
  - ❌ 否 → 平台 / 客户端 / 供应商都没变，跳过

### AGENTS.md

- [x] 流程、端口策略、工程约定有变化？
  - ❌ 否 → 只是新增 CLI 命令，不改工程约定，跳过

- [x] 新增了工作流文件？
  - ❌ 否 → 这次是代码功能，不是工作流，跳过

### 报错 / 界面文案

- [x] 新增或改了报错信息？
  - ✅ 是 → `export` 命令在配置文件不存在时报错：

    ```
    ❌ 导出失败：找不到配置文件 ~/.modeldock/config.toml
       请先运行 modeldock init 初始化配置。
    ```

    - ✅ 说清出了什么（找不到配置文件）
    - ✅ 说清怎么修（运行 init）
    - ✅ 没有暴露堆栈或内部变量名

- [x] 新增或改了界面文案？
  - ❌ 否 → 纯 CLI 命令，无界面改动，跳过

## 另一个示例：纯内部重构（不加 CHANGELOG）

假设任务目标是"重构 `src/gateway/proxy.ts` 拆分函数"，`finish` 前过 checklist：

### CHANGELOG.md

- [x] 这次改动有用户可见的行为变化吗？
  - ❌ 没有 → 纯内部重构，用户无感知
  - 跳过本节，**不加条目**

### README.md

- [x] 所有检查项都跳过（用户无感知）

### AGENTS.md

- [x] 工程约定有变化？
  - ❌ 否 → 只是拆函数，不改约定，跳过

### 报错 / 界面文案

- [x] 所有检查项都跳过（用户无感知）

结论：纯内部重构，不需要更新任何对外文档，直接 `finish`。
