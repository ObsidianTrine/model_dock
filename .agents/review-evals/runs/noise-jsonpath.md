发现 2 个问题

**1. tokenize 对不认识的句式静默吞字/改写，写入路径会悄悄落到错误键上**
`src/util/jsonpath.ts:16`（正则 `/([^[.\]]+)|\[(\d+)\]/g`）+ `:18-24`（exec 循环只消费匹配段，不校验输入是否被完整覆盖，未匹配字符被静默跳过）。实例：
- `$.a['b']`：`[` `]` 被跳过后，`'b'` 三个字符（`'` 不在排除集 `[^[.\]]` 内）整体匹配为 key，tokenize 产出 `['a', "'b'"]`——key 带引号字面量。`setPath` 会往配置里写一个名为 `'b'`（含引号）的新键，而非键 `b`，静默写错位置；`["b"]` 同理。这对「声明式 adapter pack 写客户端配置」是实打实的写坏配置路径（REVIEW.md 适配器区失败样例）。
- `$.a[-1]`：`-1` 匹配为字符串键 `'-1'`，在数组上写非索引属性，JSON/YAML 序列化时该值静默丢失。
- `$.a[0`（未闭合）：`0` 变成字符串键 `'0'`，走 key 分支绕过 `:77` 的稀疏数组越界检查，`$.a[5` + 短数组可制造稀疏数组（正是 `:76` 注释明确要防的坏数据）。

建议 tokenize 校验「去匹配字符后剩余应为空 / 结构完整」，否则按 `toSegments` 对 star 的先例（`:43`）抛可操作报错。

**2. star 后续路径遇到原始类型子节点时抛裸 TypeError（非 t() 文案）**
`src/util/jsonpath.ts:65` 对 child 无类型守卫直接递归，落入 `:72` 在原始类型上赋属性——ESM 严格模式下抛 `TypeError: Cannot create property 'b' on string 'str'`。复现：`setPath({a:{b:1}, c:'str'}, '$.*.b', 2)`（c 为字符串时崩溃）。对比同函数 `:62`（leaf 写入对 object 子节点 skip）与 `:95-98`（key 路径对非 object 子节点按需建容器）都做了兜底，唯独 star 中段递归裸崩，且报错未经 `t()` 双语化（违反工程硬性约定「错误信息必须可操作 + 双语」）。

## 存疑

- **index 段落在非数组容器上不校验**：`setPath({}, '$[0]', 1)` 走 `:74-86`，`{}.length` 为 undefined 使 `:77` 恒 false，结果产出普通对象 `{0:1}` 而非数组，序列化形态与路径语义不符。机制确证，但根因可归为调用方传入与路径不匹配的 root，且实际调用点（L2 pack plan）是否会出现该输入未查证，暂不列为确证问题。
- `$.a..b`、`$.a[*].b` 会被宽容解析为 `$.a.b` / `$.a.*.b`（`[*]` 的 `*` 恰好被当 bare star），语义碰巧正确，未报。
