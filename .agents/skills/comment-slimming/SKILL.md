# 注释瘦身（Comment Slimming）

目标：降低注释的视觉与维护负担，同时不丢失任何"代码看不出来的信息"。
完成标准：读者对系统的理解不变浅；留下的注释简洁明了；`git diff` 只含注释行；
构建与测试通过。

## 读者建模（人 + agent 双读者）

注释的读者不止人：agent 协作仓库里，接手维护的 AI agent 是第一读者。
两类读者失明方式不同，盖住测试要对两类各跑一遍：

- 人类读者有编辑器悬停与类型推导，签名/类型复述可删；
- agent 读者读原文、常在单文件上下文内改动，且有三类高发错误：对称化改写
  （把刻意的不对称"修"成对称）、模式化批量重构、跨文件复制先例。
  针对这三类错误的说"不要"注释是安全轨，一律保留。

## 核心判据

注释写 why，不写 what（Code Tells You How, Comments Tell You Why）。对每条注释问：
**把注释盖住，读者能否从代码无损得到同样的信息？** 能则删。
盖住测试对双读者各跑一遍：对人类无损、但放走某类 agent 错误（见读者建模）的注释，删不得。

TS/JS 里类型注解也是文档：签名、参数类型、返回类型、字面量联合的取值，代码已经
表达的不再复述进注释。编辑器悬停即见的字段类型说明同理。

- 注释与代码矛盾比没有注释更糟：发现陈旧注释先核实代码真实行为，改写而非删除；
  拿不准的列出并询问，不静默删。
- 被注释掉的死代码整块删除，历史在版本库里。
- **保留也要瘦身**：留下来的注释同样要简洁明了——一句话说清约束，不堆从句、
  不铺垫、不重复上下文；啰嗦的长块按 F 模式压缩。简洁不等于电报体：术语、
  单位、约束条件必须完整。

## 保留集合（默认不动）

以下七类是保留对象，删除候选必须先对照：

1. 业务/设计意图——为什么这么做，而不是做了什么
2. 并发、生命周期、竞态保护（如"AsyncLocalStorage 随异步链传播，并发请求互不串扰"）
3. 非平凡算法说明（滑动窗口与熔断、跨午夜时段归属、差分、位技巧、精度处理）
4. 平台/运行时兼容（NTFS 权限位、Windows 无信号语义、rename 运行中文件、打包边界）
5. 单位与魔法值语义（枚举取值含义、协议字段约定、状态码映射、单位换算）
6. 防 agent 误操作的安全轨——解释刻意不对称的注释（"必须省略 off：对称补上会复活
   上游 400"、"不要放宽断言"、"不要复用 X 的 wire 名"），是写给未来编辑者的禁止令
7. 配置契约字段注释——带默认值/单位/跨字段交互语义的字段说明，是该配置的唯一文档，
   按"保留并精简"处理，不按"仅复述字段名"清理

另有四类"看似可删实则必留"：

- 反直觉副作用：函数名看不出的行为（如 cmdGatewayStop "先卸自启服务，防 KeepAlive 拉锯"）
- 规范与文档引用：RFC、官方文档、本仓库 design 文档的章节号——是溯源依据，不是装饰
- 被别处交叉引用的编号体系（如"契约③"）：改编号会断链
- 问题单号与踩坑记录（JIRA-xxx、"2026-10 实测踩中：…"）：可追溯性是注释的核心价值

## 删除候选（六类模式，按此顺序分批处理）

### A. 逐字重复的样板块
同一注释块在多个文件逐字出现（典型：同一段兼容性/告警说明被复制多份）。
→ 每处压缩为一行，保留"读者就地需要的最小理由"；权威说明收敛到一处（约定文档或定义处）。

### B. 同一论据多处重复
同一事故论证/机制解释被复制到多个函数（源头 doc + 各使用点复述）。
→ 三步归一：
  1. 建归一映射表：主题 → 权威出处（定义处/首次引入处/约定文档）→ 各出现点处置；
  2. 每个出现点二分：「故事解释」压成一行指针（须带锚点名，如"竞态推演见
     fsx.ts assertNotRealHomeWrite 注"，grep 可达）；「就地约束」（动作点一句话
     do/don't）必须保留——agent 单文件上下文工作，不去查权威出处，动作点没有
     禁止令就会凭对称直觉犯错；
  3. 多 agent 协作仓库里这是占比最高的噪音模式：产出以压缩为主、直删为辅。

### C. 装饰性内容
分割线饰字（`// ---------- xxx ----------`、`// ─── xxx ───`）、纯步骤编号、
指向已不存在文档的编号。
→ 删饰字与失效编号，保留实质标题文字；仓库内真实存在的文档引用保留（见保留集合）。

### D. 复述代码
`// 认证 → 路由` 挂在 `await authenticate()` 上、`//1. detach 所有 harness` 挂在
`detachAllHarnesses()` 上、`/** token → harness id */` 挂在 `tokenHarness` 字段上。
→ 删。半句复述、半句有增量时，只留有增量的半句。

### E. 陈旧/矛盾注释
注释说的行为与代码不符（改名后的旧概念、已删除的开关、失效的端口/路径）。
→ 核实代码行为后改写。这是唯一"改写优先于删除"的类别。

### F. 冗长但信息完整的块
→ 合并句子压缩行数（4~7 行压到 2~3 行），逐约束核对不丢信息。
  压缩优于删除：信息有价值时减行数，不减信息。

## 安全边界

- **先查禁区**：读项目约定（AGENTS.md / CLAUDE.md / README / CONTRIBUTING）中
  声明不可修改的路径——vendor 依赖、node_modules、生成代码、构建产物（dist/、
  release/）。这些目录整体跳过，拿不准就跳过。
- **只改注释行**：不删改、不重排任何代码（含 import、空行、引号内内容）。
- **TS/JS 三类"假注释"——检索命中 ≠ 真注释，逐处确认再动**：
  - 字符串与正则里的 `//`（URL `https://…`、协议正则）不是注释，绝不能动；
  - 模板串（backtick）内的 `//`、`/* */`、`<!-- -->` 是生成物（内嵌 Web 页面的
    JS/CSS/HTML）的注释，可按同样判据瘦身，但模板串的转义与 `${}` 一字不动，
    改完必须跑构建/页面冒烟验证；
  - 指令注释是功能不是噪音：`#!` shebang、`/// <reference>`、`@ts-expect-error` /
    `@ts-ignore` / `eslint-disable` / `@deprecated`，一律保留。
- **模板串内的数据载体注释**：被代码回读的标记（如 plist/unit 文件里回读的
  ARGV 标记）是数据不是注释，绝不能动——与"指令注释是功能"同性质。
- **行尾对齐注释**（对象字段表 `kOk = 0; // 已受理` 的列对齐）是格式产物而非噪音，
  不做"去尾部注释"的整体清理，逐条按语义判断是否冗余。
- **JSDoc 分级**：导出 API 的 JSDoc 默认保留（编辑器提示面）；仅复述签名的删
  （`/** 添加服务 */` 挂在 addService 上）；字段 JSDoc 仅复述字段名的删，带单位/
  语义/约束的保留并精简。
- **禁止 pattern 批量删**：不许按行首 `//` 之类的模式机械删除，必须逐条语义判断。
- **执行者自防**：瘦身的执行者往往也是 agent。模式化外观 ≠ 模板噪音——同构注释
  （"2026-XX-XX 核对"、"与 XX 同思路"）可能每处携带不同增量（溯源日期、豁免条件），
  逐条核对增量后才可归入重复；批量删除前 grep 抽验 3 处以上。
- **每处删除要能说清**："读者少知道了什么、为什么没关系"。说不清就不删。

## 范围

- 用户指定了目录或文件（可多个、可混用）→ 只处理这些路径，不做全仓库扫描。
- 未指定 → 默认整个仓库的源码目录，跳过安全边界中的禁区。
- 命中禁区的文件即使被显式指定也先跳过并向用户说明，经用户确认后才处理。

## 工作流程

1. **划界**：确定范围（见上），读项目约定确定禁区与验证命令（构建/测试）。
2. **摸底**：范围较大时统计注释密度定位重灾区（POSIX shell 一行）：
   ```bash
   for f in $(find src test -name '*.ts'); do c=$(grep -cE '^\s*(//|\*|/\*)' "$f"); t=$(wc -l < "$f"); [ "$t" -gt 0 ] && echo "$c $t $f"; done | sort -rn | head -20
   ```
   用户已指定少量文件时跳过统计，直接进入评审。
3. **评审**：通读范围内文件的注释，按六类模式归类，输出处置清单
   （`文件:行号 → 模式 → 处置`）；命中 B 类主题时先产出归一映射表
   （主题 → 权威出处 → 各出现点处置），再进入瘦身。
4. **瘦身**：按类别分批修改，每批独立提交；涉及生成物模板串的批次排最后。
5. **验证**：每批后 `git diff` 确认只有注释行差异，再构建并跑受影响测试。
6. **报告**：汇总削减量（行数、占比）、逐文件改动、明确列出"保留但存疑"的
   注释供人复核。

用户要求"先出方案"时，执行 1~3 后停下等确认，不进入 4。
仓库有分支工作流约定（如 feature-branch）时，瘦身改动照走该流程。

## 报告格式

```
## 注释瘦身报告 — <范围>
- 总量：508 处 / 5012 行 → 净删 52 行（-10%）
- 分模式统计：A 14 | B 18 | C 5 | D 9 | E 2 | F 4
- 归一映射表：<主题> → 权威出处 <文件:行>；压缩 N 处 / 就地保留 M 处
- 保留但存疑（3 处，请复核）：
  - foo.ts:120 — "看似复述 onLogout，实为解释取消定时器的隐含副作用" → 已保留
```

## Before / After 示例

**C 装饰性分割线**（饰字删除，实质标题保留）：
```ts
// Before
// ─── 安装形态识别 ────────────────────────────────────────────────

// After
// 安装形态识别
```

**B 同一论据多处重复**（JSDoc 为权威，就地只留增量）：
```ts
// Before（函数 JSDoc 已写明沙箱只放行可重定向的 npm 安装，体内再复述）
// 沙箱内只放行 npm 全局安装：脚本类落点由第三方脚本决定，会写进真机。

// After（就地只留 JSDoc 没有的增量）
// MODELRDOCK_INSTALL_ALLOW_ANY=1 为单测桩命令放行，受控环境专用。
```

**B 归一**（同一论据多处 → 权威 1 处 + 指针/就地约束；多 agent 仓库的主噪音模式）：
```ts
// Before（同一竞态推演在 3 个函数各展开一遍，各 4 行）
// 先落配置后动密钥：反序会在配置写失败时留孤儿密钥条目，且写入窗口内并发读者……

// After（权威处保留完整推演；其余出现点压成一行指针 + 就地约束）
// 权威处（首次引入点）：
// 先落配置后动密钥：反序会在配置写失败时留孤儿密钥条目，且写入窗口内并发读者……
// 其余出现点：
// 顺序不可反，先 config 后 secrets（推演见 hServiceUpdate 注）
```

**D 复述删减**（调用名已说清的事不再写一遍）：
```ts
// Before
//1. detach 所有 harness
await detachAllHarnesses(...)

// After（整行删）
await detachAllHarnesses(...)
```

**保留也要精简**（信息有价值但铺垫啰嗦，压行数不减信息）：
```ts
// Before（5 行流水账）
// 求值当前命中的全部窗口。首先判断服务是否已停用，如果已停用则直接返回空数组，
// 否则遍历所有配置的窗口，逐一判断当天是否生效，再把当前时间与窗口的起止时间
// 做比较，开始时间包含在区间内而结束时间不包含……

// After（2 行，约束全保留）
// 求值当前命中的全部窗口（已停用 → 空数组）。start 含、end 不含；end < start 视为跨午夜，
// 后半夜归属起始日——否则「周五 22:00-06:00」周六凌晨因 dow 不符漏判。
```

**保留集合的"看似复述"**（勿删）：
```ts
/** 停掉受管网关实例（生产实现 = cmdGatewayStop；先卸自启服务防 KeepAlive 拉锯） */
```
"防 KeepAlive 拉锯"是函数名看不出的反直觉行为，必须保留。

**保留集合第 6 类"防复辟安全轨"**（勿删——删了未来编辑者会凭对称直觉复活 bug）：
```ts
// 必须省略 off：dsh 的 resolver 把『声明 off: null』落成 map 无 off 键，
// 上游对无 off 键模型返回 400。对称补上 off 看似更整齐，实为复辟。
```

**伪模板陷阱**（同构外观 ≠ 模板噪音，逐处核增量后才可归入 B 类）：
```ts
// 2026-10-12 核对（官方文档）：端点已下线 /v1/completions
// 2026-10-28 核对（实测）：base_url 必须带 /v1 前缀，易配错
```
看似同构的"日期核对"模板，每处携带不同溯源事实——全部保留。

**假注释**（不是注释，绝不能动）：
```ts
const res = await fetch('https://example.com/v1/models')  // 字符串里的 //
const re = /^[a-z]+:\/\/.+/                               // 正则里的 //
const page = `<style>/* 内嵌页面的 CSS 注释 */</style>`    // 模板串里的生成物注释
```
